# restaurant-url-finder

キーワード・エリア・現在地でお店を検索し、気に入った店を「行きたい店」に保存、
相手ごとの「共有ボックス」にまとめてリンクを発行できるWebアプリです。
デート・会食の候補選び〜共有までを1つのアプリで完結させることを想定しています。

検索はGoogle(Places API)を起点にエリア/ジャンル/現在地で複数候補を探し、
各候補について同名店舗がホットペッパーにあれば、画像・予算・ジャンルなど情報が
豊富なホットペッパー側を優先して表示します(表示優先度: ホットペッパー→Google)。

食べログ(Google Custom Search API経由)は現状未使用です。`src/services/tabelogViaGoogle.js`
は実装済みで残してあるので、必要になれば再度組み込めます。

## セットアップ

```bash
npm install
cp .env.example .env
```

`.env` に以下のAPIキーを設定してください。

- **HOTPEPPER_API_KEY**(無料)
  - https://webservice.recruit.co.jp/ で「ホットペッパー グルメサーチAPI」を無料登録して取得
- **GOOGLE_PLACES_KEY**(要Billing設定)
  - Google CloudでBillingアカウントを有効化した上で、「Places API (New)」を有効化してAPIキーを発行
  - 暴走課金を防ぐため、Cloud Consoleの「APIとサービス→割り当て」でPlaces APIの
    1日あたりクエリ数に低めの上限を設定しておくことを強く推奨します(上限到達時は
    アラートではなくAPIエラーになるだけで、課金は発生しません)

キーが未設定の場合は検索結果にその旨のメッセージが表示されます(アプリ自体は起動できます)。

## 起動

```bash
npm start
```

http://localhost:3000 を開いてください。

## 使い方

1. キーワード(ジャンル等・任意)とエリア(任意)を入力するか、「現在地から探す」で検索
2. 検索結果の各カードから「♡ 行きたい店に追加」で保存(ブラウザのlocalStorageに保存されます)
3. 「行きたい店」セクションのカードから「ボックスへ追加」で、共有したい相手ごとのボックスに振り分け
   (ボックスは複数作成でき、同じ店を複数のボックスに入れることもできます)
4. 各ボックスの「共有リンクを作成」→「コピー」でURLをコピーし、LINEなどでそのまま送るだけで、
   相手のブラウザでも同じ候補リストを閲覧できます(相手側での操作・アカウント登録は不要)

## 遠隔地の相手と共有するために(ネットへの公開)

共有リンクの中身は候補データをURL自体に埋め込んでいるだけ(サーバー側にデータ保存はしません)なので、
`http://localhost:3000` のままでは自分のPC上でしか開けず、外出先の相手には届きません。
相手が別の場所・スマホ回線からリンクを開けるようにするには、このアプリをネット上に公開(デプロイ)する必要があります。

無料で手軽な例として [Render](https://render.com/) を使う手順です(GitHubアカウントが必要です)。

1. このプロジェクトをGitHubリポジトリにpushする
2. Renderにサインアップし、「New +」→「Web Service」から今のGitHubリポジトリを連携する
3. Build Command: `npm install` / Start Command: `npm start` を設定
4. 「Environment」タブで `.env` と同じ内容(`HOTPEPPER_API_KEY` / `GOOGLE_PLACES_KEY`)を環境変数として登録する
5. デプロイ完了後に発行される `https://xxxx.onrender.com` が公開URL。以降はこのURLで検索・共有リンク作成を行う

GitHubリポジトリの作成・Renderへのサインアップ・pushなどのアカウントに関わる操作はご自身で行ってください。
